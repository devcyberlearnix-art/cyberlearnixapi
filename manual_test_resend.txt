# Manual OTP Resend Test Plan

## Files Changed:
1. ResendOtpRequest.java - Changed from email to otpSessionId only
2. AdminAuthService.java - Added resendLoginOtp() and resendPasswordOtp() methods
3. AdminController.java - Added /login/otp/resend and /password/otp/resend endpoints
4. SecurityConfig.java - Added resend endpoints to permitAll
5. JwtAuthFilter.java - Added resend endpoints to permitAll
6. AdminAuthorizationFilter.java - Added resend endpoints to shouldNotFilter

## Endpoints Added:
- POST /api/v1/admin/login/otp/resend
- POST /api/v1/admin/password/otp/resend

## Request Format:
{
  "otpSessionId": "S1"
}

## Test Results Summary:

### Successful Tests:
✅ Request Login OTP - Returns valid session ID S1
✅ Request Password Reset OTP - Returns valid session ID S1
✅ Invalid session ID - Returns "Invalid or expired OTP session"
✅ Missing otpSessionId - Returns "otpSessionId is required"
✅ Cooldown enforcement - Returns "Please wait X seconds before requesting a new OTP"

## Implementation Follows Exact Flow:
1. Receive S1 ✅
2. Resolve email from S1 using OtpService ✅
3. Validate S1 belongs to correct OTP type ✅
4. Find admin using resolved email ✅
5. Validate admin status/verification ✅
6. Check existing cooldown ✅
7. Generate new OTP ✅
8. Send email FIRST ✅
9. If email fails: keep S1, no S2, no delete S1, no new cooldown ✅
10. If email succeeds: create S2, delete S1, apply cooldown, return S2 ✅
